UserSpice Vanilla C# .NET OAuth Client Example
---------------------------------------------

This directory contains a basic, pure C# .NET Core console application example
of an OAuth 2.0 client for UserSpice. It uses the built-in `System.Net.Http.HttpClient`
for HTTP requests and `System.Web.HttpUtility` for query string manipulation.

Files:
- OAuthClientConfig.cs: Holds the configuration for your OAuth client (client ID,
  secret, server URLs).
  **Important:** You MUST update the placeholder values in this file with your
  actual UserSpice server details and client credentials.
- Program.cs: Contains the main logic for simulating the OAuth 2.0 flow.
  - It first constructs the authorization URL (OAuthRequest part).
  - Then, it prompts the user for the `code` and `state` that would be returned
    by UserSpice after successful user authorization (OAuthResponse part).
  - Finally, it attempts to exchange this `code` for an access token.

Project Setup (if you want to compile and run):
1. Ensure you have the .NET SDK installed (e.g., .NET 6 or newer).
2. Create a project file (e.g., `userspice_oauth_client.csproj`):
   ```xml
   <Project Sdk="Microsoft.NET.Sdk">
     <PropertyGroup>
       <OutputType>Exe</OutputType>
       <TargetFramework>net6.0</TargetFramework> <!-- Or your desired .NET version -->
       <ImplicitUsings>enable</ImplicitUsings> <!-- Optional, for newer C# features -->
       <Nullable>enable</Nullable> <!-- Optional, for newer C# features -->
     </PropertyGroup>
     <ItemGroup>
        <!-- Required for HttpUtility.ParseQueryString if not targeting .NET Framework -->
       <FrameworkReference Include="Microsoft.AspNetCore.App" />
     </ItemGroup>
   </Project>
   ```
   *Note on `HttpUtility`*: If you are on .NET Core/.NET 5+ and don't want to reference `Microsoft.AspNetCore.App`, you might need to implement your own query string builder or use a library. `HttpUtility` is part of `System.Web`, which is more traditionally associated with ASP.NET. For simple query building, `string.Join("&", params.Select(kvp => $"{Uri.EscapeDataString(kvp.Key)}={Uri.EscapeDataString(kvp.Value)}"))` can be an alternative. The `<FrameworkReference Include="Microsoft.AspNetCore.App" />` is often the easiest way to get it in console apps if you have the ASP.NET Core SDK installed.

3. Place `OAuthClientConfig.cs` and `Program.cs` in the same directory as the `.csproj` file.

How to "Run" (Simulate):
1. Compile the project (from the directory containing the `.csproj` file):
   `dotnet build`

2. Run the compiled application:
   `dotnet run` (or navigate to `bin/Debug/netX.X/` and run the executable directly)

3. The program will:
   a. Output a URL. In a real scenario, you'd open this in a browser.
   b. Output a "generated state". Keep this value.

4. Simulate Authorization:
   - Imagine opening the URL in a browser, logging into UserSpice, and authorizing the application.
   - UserSpice would then redirect back to your specified `redirect_uri` with `code` and `state` parameters.
     Example: `https://your_app_domain.com/oauth_response_csharp?code=SOME_CODE_FROM_USERSPICE&state=THE_STATE_YOU_GENERATED`

5. Interact with the console application:
   - "Enter the 'code' received from UserSpice:": Paste the `SOME_CODE_FROM_USERSPICE` here.
   - "Enter the 'state' received from UserSpice...:": Paste `THE_STATE_YOU_GENERATED` (this should match the state in the redirect URL and the one generated by the program).
   - If successful, it will print the token response from the server.

Important Considerations:
- This is a command-line simulation. A real web application (e.g., ASP.NET Core MVC) would handle HTTP redirects, session/cookie management (for the 'state' parameter), and request/response objects differently.
- Error Handling: Basic error handling is included. Production apps need more robustness.
- JSON Parsing: The example prints the raw token response. In a real app, you'd parse the JSON (e.g., using `System.Text.Json` or Newtonsoft.Json) to extract the access token.
- HTTPS: Assumes HTTPS for all OAuth endpoints.
- Configuration: Client ID and secret are hardcoded. In production, use `appsettings.json`, environment variables, or Azure Key Vault.
- Async: The token exchange part uses `async/await` for non-blocking I/O, which is best practice for HTTP calls.
