Wiki.js UserSpice OAuth Authentication Notes
--------------------------------------------

This document provides instructions on how to configure Wiki.js to use UserSpice as an OAuth 2.0 authentication provider, allowing users to log in with their UserSpice credentials.

Wiki.js uses Passport.js for authentication and allows adding custom OAuth 2.0 providers through its administration interface. This guide focuses on configuring a generic OAuth 2.0 strategy.

**Assumptions:**

*   You have a working UserSpice installation with the OAuth Server plugin enabled.
*   You have administrative access to your Wiki.js installation (version 2.x or later).
*   UserSpice's OAuth server provides a standard user information endpoint (`/api.php` by default) that returns user details in JSON format.

**Steps for Integration:**

**Part 1: UserSpice OAuth Server Configuration**

1.  **Create an OAuth Client in UserSpice:**
    *   In your UserSpice installation, navigate to the OAuth Server plugin settings.
    *   Create a new OAuth client application for Wiki.js.
    *   **Client Name:** A descriptive name, e.g., "Wiki.js Login".
    *   **Redirect URI / Callback URL:** This is critical. You will obtain this URL from Wiki.js in Part 2, Step 3. It will look something like:
        `https://your-wikijs-domain.com/login/userspice/callback` (The `userspice` part will match the "Strategy Key / Slug" you define in Wiki.js).
        **For now, you can use a placeholder or your Wiki.js base URL; you will update this later.**
    *   Note down the **Client ID** and **Client Secret** provided by UserSpice. These are needed for the Wiki.js configuration.

**Part 2: Wiki.js Authentication Module Configuration**

1.  **Access Authentication Settings:**
    *   Log in to your Wiki.js instance as an administrator.
    *   Navigate to "Administration" (usually an icon in the sidebar).
    *   Go to "Authentication".

2.  **Add a New Strategy:**
    *   Scroll down to the list of available authentication strategies.
    *   Click the "Add New Strategy" button.
    *   Select "OAuth 2.0" (Generic) from the list of providers.

3.  **Configure the UserSpice OAuth 2.0 Strategy:**
    *   **Strategy Key / Slug:** Enter a unique key for this strategy, e.g., `userspice`. This will be part of the callback URL.
        *   **Important:** Note the "Callback URL / Redirect URI" that Wiki.js displays here. It will be something like `https://your-wikijs-domain.com/login/userspice/callback`. **You must use this exact URL in your UserSpice client configuration (Part 1, Step 1).**
    *   **Strategy Name (Display Name):** `UserSpice` (or "Login with UserSpice"). This is what users will see on the login button.
    *   **Client ID:** Paste the Client ID from UserSpice.
    *   **Client Secret:** Paste the Client Secret from UserSpice.
    *   **Authorization URL:** The full URL to UserSpice's authorization endpoint.
        Example: `https://your-userspice-server.com/usersc/plugins/oauth_server/auth.php`
    *   **Token URL:** The full URL to UserSpice's token endpoint.
        Example: `https://your-userspice-server.com/usersc/plugins/oauth_server/auth.php` (often the same as auth URL for UserSpice)
    *   **User Profile URL (User Info Endpoint):** The full URL to UserSpice's API endpoint that returns user details.
        Example: `https://your-userspice-server.com/usersc/plugins/oauth_server/api.php`
    *   **Scope:** Space-separated list of scopes.
        Example: `profile email` (ensure these scopes grant access to the fields you want to map).
    *   **Pass token via (for User Profile URL):**
        *   UserSpice's simple API usually expects the access token as a query parameter. Select **Query Parameter**.
        *   **Query Parameter Name:** `access_token` (This is the typical parameter name for UserSpice's simple API).
        *   (Alternatively, if your UserSpice OAuth server supports Bearer tokens for the API endpoint, you could select "Authorization Header" with "Bearer" prefix, but query parameter is more common for the basic UserSpice API.)
    *   **User ID Path (Path to unique user ID):** JSON path to the unique identifier in the User Profile JSON response.
        Example: `id` (if UserSpice API returns `{"id": 123, ...}`)
    *   **Username Path (Path to username):** JSON path to the username.
        Example: `username`
    *   **Display Name Path (Path to display name):** JSON path to the user's full name.
        Example: You might need to use `username` if a combined `displayName` or `name` field isn't available, or if UserSpice returns `fname` and `lname`, Wiki.js might not be able to combine them directly with generic OAuth2. Using `username` or `email` as display name is a fallback. If UserSpice returns a `name` field, use `name`.
    *   **Email Path (Path to email address):** JSON path to the email.
        Example: `email`
    *   **Picture Path (Path to profile picture URL - Optional):** JSON path if UserSpice API provides a profile picture URL.
        Example: `profile_pic_url` (if such a field exists in UserSpice API response)
    *   **Allow login for existing users only:** Uncheck this if you want to allow auto-registration of new users from UserSpice.
    *   **Automatically create new user:** Check this if you want users who authenticate successfully via UserSpice but don't have a Wiki.js account to have one created automatically.
    *   **Default Group for New Users:** Select the Wiki.js group to assign to newly created users.
    *   **Map to specific group (Optional):** You can map users to a specific Wiki.js group based on this authentication method.

4.  **Enable and Save:**
    *   Ensure the "Enable" toggle for this strategy is ON.
    *   Click "Apply" or "Save" at the top or bottom of the Wiki.js admin page.

5.  **Update UserSpice Client Configuration:**
    *   Go back to your UserSpice OAuth Server settings (Part 1, Step 1).
    *   Update the **Redirect URI** for the Wiki.js client with the exact Callback URL provided by Wiki.js in Step 3 (e.g., `https://your-wikijs-domain.com/login/userspice/callback`).

**Testing:**

1.  Log out of Wiki.js or open an incognito browser window.
2.  Navigate to your Wiki.js login page.
3.  You should see a "Login with UserSpice" (or the Strategy Name you configured) button.
4.  Click the button. You should be redirected to your UserSpice server.
5.  Log in with valid UserSpice credentials.
6.  Authorize Wiki.js if UserSpice prompts for authorization.
7.  You should be redirected back to Wiki.js and logged in.
    *   If auto-creation is enabled and the user is new, a Wiki.js account should be created for them.

**Troubleshooting:**

*   **Check Wiki.js Logs:** Go to Administration > Utilities > Logs in Wiki.js.
*   **Check UserSpice OAuth Server Logs:** If available.
*   **Callback URL Mismatch:** This is a very common issue. Double-check that the Redirect URI in UserSpice exactly matches the Callback URL shown in the Wiki.js strategy settings.
*   **JSON Path for User Fields:** Ensure the paths (`id`, `username`, `email`, etc.) correctly point to the fields in the JSON response from UserSpice's User Profile URL (`/api.php`). You can test the User Profile URL with `curl` or Postman using a valid access token to see the exact JSON structure.
    Example UserSpice API response might be: `{"id":1,"username":"admin","fname":"Admin","lname":"User","email":"admin@example.com", ...}`
    So, `id` path is `id`, `username` path is `username`, `email` path is `email`. For Display Name, you might use `username` or see if Wiki.js has advanced mapping.
*   **Scope:** Ensure the requested scopes (`profile email`) are sufficient for UserSpice to return the necessary fields.
*   **HTTPS:** Both Wiki.js and UserSpice must use HTTPS for secure operation.
*   **Token Passthrough:** Verify the "Pass token via" setting (Query Parameter vs. Authorization Header) matches how your UserSpice API endpoint expects the access token.

This configuration-based approach should work if UserSpice's OAuth implementation is standard. If there are specific needs not covered by Wiki.js's generic OAuth 2.0 provider settings, a custom Passport.js strategy might theoretically be developed for Wiki.js, but that's a much more involved coding task and usually not necessary.
