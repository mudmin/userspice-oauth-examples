Drupal UserSpice OAuth Module Notes
-----------------------------------

This directory (`userspice_oauth`) contains the files for a Drupal module that allows users to log in using their UserSpice credentials via OAuth2.

**Module Files:**

*   `userspice_oauth.info.yml`: Defines the module, its dependencies, and configuration route.
*   `userspice_oauth.routing.yml`: Defines URL paths for the OAuth callback, the redirection trigger, and the admin settings form.
*   `userspice_oauth.links.menu.yml`: Adds a link to the module's settings page in the Drupal admin menu (Configuration > Web services).
*   `src/Form/SettingsForm.php`: Implements the admin configuration form where site administrators set up UserSpice server details, client ID/secret, etc.
*   `src/Controller/UserSpiceOAuthController.php`: Handles the main OAuth logic:
    *   Redirecting users to UserSpice for authentication.
    *   Processing the callback from UserSpice.
    *   Exchanging the authorization code for an access token.
    *   Fetching user information from UserSpice.
    *   Logging in existing Drupal users or creating new ones based on UserSpice data.

**Installation:**

1.  **Place the Module:**
    *   Copy the entire `userspice_oauth` directory into your Drupal installation's `modules/custom/` directory. If `custom` doesn't exist, create it.
    *   The path should look like: `<drupal_root>/modules/custom/userspice_oauth`.

2.  **Enable the Module:**
    *   Log in to your Drupal site as an administrator.
    *   Navigate to "Extend" (or `/admin/modules`).
    *   Find "UserSpice OAuth" in the list (it should be under the "UserSpice" package).
    *   Check the box next to it and click "Install" at the bottom of the page.
    *   Drupal will enable the module and its dependencies.

**Configuration:**

1.  **Configure Settings:**
    *   After installation, navigate to "Configuration" > "Web services" > "UserSpice OAuth" (or go directly to `/admin/config/userspice_oauth/settings`).
    *   You will need to configure the following:
        *   **UserSpice Server URL:** The full base URL of your UserSpice installation (e.g., `https://your-userspice-domain.com/usersc/`).
        *   **Client ID:** The Client ID for your OAuth client from UserSpice.
        *   **Client Secret:** The Client Secret for your OAuth client. (Note: For better security in production, consider using the Key module to store the client secret instead of a plain config field).
        *   **Authorization, Token, User Info Endpoint Paths:** Relative paths for these UserSpice API endpoints. Defaults are provided.
        *   **Scope:** Space-separated scopes (e.g., `profile email`). `email` is crucial.
        *   **Auto-create Drupal User:** Enable if you want new Drupal users created automatically.

2.  **Set Redirect URI in UserSpice:**
    *   In your UserSpice OAuth Server plugin configuration (for this client), set the **Redirect URI**.
    *   The Redirect URI for this Drupal module will be:
        `https://your-drupal-site.com/userspice_oauth/callback`
        Replace `https://your-drupal-site.com` with your actual Drupal site's base URL. Ensure this matches exactly.

**Usage - Adding a Login Link/Button:**

This module provides a path to initiate the login: `/userspice_oauth/redirect` (or the alias `/user/login/userspice`). You need to add a link to this path on your site, typically on the login page or in a block.

1.  **Site-Wide Block (Example):**
    *   Go to "Structure" > "Block layout" (`/admin/structure/block`).
    *   Click "Place block" in a region (e.g., "Content" or "Sidebar").
    *   Choose "Custom block" > "Basic block" or add a new "Custom block" from "Custom block library".
    *   In the block content, add a link:
        `<a href="/userspice_oauth/redirect" class="button button--primary">Login with UserSpice</a>`
        (Or use `<a href="/user/login/userspice">...</a>`)
    *   Configure block visibility (e.g., show only on `/user/login` page, and only for anonymous users).

2.  **Template Override (for `user.login` form):**
    *   If you want to integrate it more deeply into the Drupal login form, you might need to override the `user_login_form.html.twig` template (or similar) in your theme and add the link there.

3.  **Menu Item:**
    *   You could add a menu item linking to `/userspice_oauth/redirect` or `/user/login/userspice`.

**Important Notes:**

*   **HTTPS:** Both your Drupal site and UserSpice server must run on HTTPS.
*   **UserSpice API:** Assumes the UserSpice API returns user data including `email` and `username`. Adjust the controller if needed.
*   **External Auth Module:** For more robust handling of external identities, linking multiple OAuth providers, or more complex user mapping, consider integrating with the `externalauth` module. This example provides a basic direct implementation.
*   **Error Logging:** Check Drupal's logs ("Reports" > "Recent log messages") for any errors.
*   **Dependencies:** Uses Drupal Core services (HTTP Client, Config, User). `GuzzleHttp\ClientInterface` is provided by Drupal Core.
*   **Security:** Storing client secrets directly in config can be a risk. For production, modules like `key` are recommended to manage secrets.
*   **Username Conflicts:** The module has basic logic to handle cases where a UserSpice username might already exist in Drupal for a different user. It will attempt to create a unique username.
*   **User Roles:** Newly created users get the default "authenticated user" role. For more complex role mapping from UserSpice to Drupal, the module would need to be extended.
