UserSpice Dart (Flutter Conceptual) OAuth Client Example
-------------------------------------------------------

This directory contains a Dart command-line application example demonstrating the
core logic for an OAuth 2.0 client for UserSpice. While the `.dart` files can be run
from the command line, the intention is to show the Dart code that would be part of a
Flutter application.

Flutter apps have specific ways to handle opening URLs (`url_launcher`) and catching
redirects via custom URI schemes or universal links (`app_links`, `uni_links`, or
packages like `flutter_web_auth` / `flutter_appauth` which simplify the flow).
This example focuses on the HTTP requests and data handling in pure Dart.

Files:
- pubspec.yaml: Defines project metadata and dependencies. Crucially, it includes
  the `http` package for making HTTP requests. You might also add `uuid` for
  better state generation if building this out.
- lib/oauth_client_config.dart: Holds the configuration for your OAuth client.
  **Important:** You MUST update placeholder values. In Flutter, config might be
  managed via `--dart-define` at build time or embedded in files.
- bin/oauth_request.dart: A command-line script simulating the first step of OAuth.
  It constructs the authorization URL.
- bin/oauth_response.dart: A command-line script simulating the callback handling.
  It prompts for the 'code' and 'state', then exchanges the code for an access token
  using the `http` package.

How to "Run" (Simulate Dart Command-Line Scripts):
1. Ensure you have the Dart SDK installed (https://dart.dev/get-dart).
   If you have Flutter installed, Dart SDK is included.

2. Navigate to the `dart_flutter` directory in your terminal.

3. Get dependencies (this will download the `http` package and any others):
   `dart pub get`

4. Run `oauth_request.dart` to get the authorization URL:
   `dart run bin/oauth_request.dart`
   (or `dart bin/oauth_request.dart` on older Dart versions)
   - This will output a URL. In a Flutter app, you'd use `url_launcher` or a
     web auth package to open this.
   - It will also output a "generated state". Keep this value. In Flutter, you'd
     store this securely (e.g., `flutter_secure_storage`) to verify upon callback.

5. Simulate Authorization:
   - Imagine the URL opening, the user logging into UserSpice, and authorizing.
   - UserSpice redirects to your `redirect_uri` with `code` and `state`.
     Example for web: `https://your_app_domain.com/oauth_response_dart?code=CODE&state=STATE`
     Example for mobile: `yourcustomscheme://oauth/callback?code=CODE&state=STATE`
     A Flutter app would intercept this redirect.

6. Run `oauth_response.dart` to exchange the code:
   `dart run bin/oauth_response.dart`
   - The script will prompt:
     - "Enter the 'code' received...": Paste the code from the simulated redirect.
     - "Enter the 'state' received...": Paste the state from the redirect.
     - "Enter the original 'state' you stored...": Paste the state generated by `oauth_request.dart`.
   - If successful, it prints the token response.

From Command-Line to Flutter App:
- URL Launching: Instead of printing the auth URL, a Flutter app would use `url_launcher` to open it in a browser/webview, or a specialized package like `flutter_appauth` or `flutter_web_auth` that handles the in-app browser tab and listens for the redirect.
- Redirect Handling: The `redirect_uri` in Flutter mobile apps is often a custom URI scheme (e.g., `myapp://callback`). The app must be configured to handle these deep links. Packages like `uni_links` or `app_links` can help, or the auth package might manage this.
- State Management: The 'state' parameter and tokens would be managed securely, often using `flutter_secure_storage`.
- HTTP Requests: The `http` package usage shown in `oauth_response.dart` is directly applicable in Flutter.
- User Interface: Obviously, all of this would be wrapped in Flutter widgets to provide a user interface.

Important Considerations:
- This is a command-line simulation. A Flutter app provides a rich UI and platform integrations.
- PKCE: For public clients like mobile apps, the PKCE (Proof Key for Code Exchange) extension to OAuth 2.0 is highly recommended for added security. This example does not implement PKCE to keep it aligned with the simpler server-side examples, but it's a crucial addition for production mobile apps. `flutter_appauth` typically handles PKCE.
- Configuration: Securely manage client ID and other sensitive details.
