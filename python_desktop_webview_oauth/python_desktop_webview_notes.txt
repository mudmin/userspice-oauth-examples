Python Desktop WebView OAuth Example for UserSpice
-------------------------------------------------

This directory contains an example of how a Python desktop application can perform OAuth 2.0 authentication with UserSpice using an embedded web browser (WebView) and a local HTTP server to handle the callback. This example uses `PyQt6` with `QWebEngineView` for the WebView and Python's built-in `http.server` for the callback.

**Files:**

*   `main_webview_oauth.py`: The main Python script. It sets up a simple PyQt6 GUI with an embedded QWebEngineView, starts a local HTTP server, navigates the WebView to the UserSpice authorization URL, and handles the OAuth token exchange after the callback.
*   `requirements.txt`: Lists the Python package dependencies (`PyQt6`, `PyQt6-WebEngine`, `requests`).

**Core Concepts:**

1.  **Embedded WebView:** The application displays the UserSpice login and authorization page directly within a `QWebEngineView` widget. This provides a more integrated experience than opening the system browser.
2.  **Local HTTP Callback Server:**
    *   A simple HTTP server is started on `localhost` on a specific port (e.g., `http://localhost:8989/callback`).
    *   This `REDIRECT_URI` must be registered with your UserSpice OAuth client application.
    *   When UserSpice authorizes the user, it redirects to this local URI.
    *   The embedded WebView navigates to this local URL.
    *   Our local HTTP server handles the `/callback` request, extracts the `code` and `state` parameters from the query string.
3.  **State Parameter (CSRF Protection):**
    *   A unique `state` parameter is generated by the Python app and included in the authorization request.
    *   This same `state` parameter must be returned by UserSpice in the callback. The app verifies it to prevent Cross-Site Request Forgery (CSRF) attacks.
4.  **Authorization Code Flow:**
    *   The app requests an `authorization_code` from UserSpice.
    *   After receiving the code via the local callback, the app exchanges this code (along with the `client_id` and `client_secret`) for an `access_token` by making a POST request to UserSpice's token endpoint.
    *   **Security Note:** For desktop applications, storing a `client_secret` can be risky. The PKCE (Proof Key for Code Exchange) extension to OAuth 2.0 is highly recommended for public clients like desktop apps as it doesn't require a client secret for the token exchange. This example uses the standard Authorization Code flow which *does* require the client secret for the token exchange step. UserSpice's OAuth server would need to support PKCE for that flow.
5.  **Access Token Usage:** Once the access token is obtained, it can be used to make authenticated requests to UserSpice API endpoints (e.g., to fetch user information).

**Setup and Running:**

1.  **Create a Virtual Environment (Recommended):**
    ```bash
    python -m venv venv
    source venv/bin/activate  # On Windows: venv\Scripts\activate
    ```

2.  **Install Dependencies:**
    ```bash
    pip install -r requirements.txt
    ```
    *Note on PyQt6/PyQtWebEngine:* Installation can sometimes be tricky depending on your OS and Python version. Ensure you have compatible Qt libraries. If `pip install` fails, you might need to consult PyQt documentation or look for pre-compiled binaries for your system. On some Linux systems, you might need to install system packages like `libxkbcommon-x11-0` or specific Qt WebEngine runtime components.

3.  **Configure UserSpice Details:**
    *   Open `main_webview_oauth.py`.
    *   Update the placeholder values for `USERSPICE_SERVER_URL`, `CLIENT_ID`, and `CLIENT_SECRET` with your actual UserSpice OAuth server details.
    *   Ensure the `REDIRECT_URI` in the script (`http://localhost:8989/callback` by default) is registered as a valid Redirect URI in your UserSpice OAuth client application settings.

4.  **Run the Application:**
    ```bash
    python main_webview_oauth.py
    ```

5.  **Authentication Flow:**
    *   A window will appear showing the UserSpice login page.
    *   Log in with UserSpice credentials.
    *   Authorize the application if prompted.
    *   UserSpice will redirect to the local callback URL (e.g., `http://localhost:8989/callback?code=...&state=...`).
    *   The embedded WebView will display this page (which our local server serves with a "Success" message).
    *   The local server will print the received code and state to the console.
    *   After you close the GUI window, the script will proceed to exchange the code for an access token and fetch user info, printing results to the console.

**Important Considerations & Improvements:**

*   **PKCE:** For enhanced security in a public client like a desktop app, implement the PKCE flow if your UserSpice OAuth server supports it. This avoids the need to embed the `client_secret` for the token exchange.
*   **Error Handling:** The example has basic error handling. A production app would need more robust error display and recovery mechanisms.
*   **GUI Responsiveness:** The current example's main thread waits for the Qt app to close before processing the token. In a more complex GUI, you'd use Qt's signals and slots or timers to handle the OAuth completion asynchronously without blocking the GUI or main thread in a polling loop. The local HTTP server runs in a separate thread.
*   **Secure Token Storage:** If access tokens need to be stored persistently, use secure storage mechanisms provided by the operating system (e.g., Windows Credential Manager, macOS Keychain, Linux Secret Service).
*   **State Generation:** The `expected_state` is currently hardcoded. Generate a cryptographically secure random string for the state parameter in a real application and store it temporarily (e.g., in a member variable) for verification.
*   **Server Shutdown:** The local HTTP server shutdown is basic. More robust applications might use `QTcpServer` for better integration with the Qt event loop or more sophisticated thread management for the Python `HTTPServer`.
*   **User Experience:** The current success page in the WebView is minimal. You could make it more user-friendly or have it auto-close the WebView/window upon success using JavaScript communication with the Python app.
*   **Alternative WebView Libraries:** If PyQt is not suitable, other libraries like `cefpython` or even simpler ones (though often with fewer features) could be adapted. The core logic of local callback server and token exchange remains similar.

This example provides a conceptual framework. Adapting it to a full-fledged application will require further refinement based on specific needs.
