Unity UserSpice OAuth Example (System Browser + Custom URI Scheme)
-----------------------------------------------------------------

This directory contains a C# script (`UserSpiceOAuthHandler.cs`) for Unity, demonstrating how to implement OAuth 2.0 authentication with UserSpice. This method uses the system's default web browser for the UserSpice login/authorization page and a custom URI scheme to redirect the user back to the Unity application.

**Files:**

*   `UserSpiceOAuthHandler.cs`: A Unity C# script. Attach this to a GameObject in your scene. It handles:
    *   Constructing the UserSpice authorization URL.
    *   Opening the URL in the system browser (`Application.OpenURL()`).
    *   Receiving the callback via a custom URI scheme (e.g., `mygame://oauth/callback`).
    *   Parsing the `authorization_code` and `state` from the activation URL.
    *   Using `UnityEngine.Networking.UnityWebRequest` to exchange the code for an access token and fetch user information from UserSpice.
    *   Provides public events (`OnOAuthLoginSuccess`, `OnOAuthLoginFailed`) for other game scripts to subscribe to.

**Core Concepts:**

1.  **System Browser for Authorization:** The UserSpice login and authorization page is opened in the device's default web browser (or an in-app browser tab like SFSafariViewController/Chrome Custom Tabs if `Application.OpenURL` triggers that behavior on mobile). This is generally more secure than using an embedded WebView directly for login credentials.
2.  **Custom URI Scheme:**
    *   Your Unity application registers a unique URI scheme (e.g., `myunitygame://`).
    *   The `REDIRECT_URI` configured in UserSpice and used by the script is set to this custom scheme (e.g., `myunitygame://oauth/callback`).
    *   When UserSpice completes authorization, it redirects to this URI. The operating system then launches or brings your Unity application to the foreground, passing the full callback URL.
3.  **Deep Link Activation:** The `UserSpiceOAuthHandler` script subscribes to `Application.deepLinkActivated`. When the app is activated by the custom URI, this event fires, providing the callback URL.
4.  **State Parameter:** Used for CSRF protection.
5.  **Authorization Code Flow:**
    *   The script obtains an `authorization_code`.
    *   This code is exchanged for an `access_token` using `UnityWebRequest`.
    *   **Security (PKCE):** This example uses the standard Authorization Code flow where a `client_secret` is used for the token exchange. For client-side applications like games, PKCE (Proof Key for Code Exchange) is highly recommended as it doesn't require embedding the `client_secret`. If UserSpice OAuth server supports PKCE, the flow should be adapted. Storing `client_secret` in a compiled game is a security risk.
6.  **Access Token Usage:** The obtained access token is used to fetch user details from UserSpice's API endpoint, again using `UnityWebRequest`.

**Setup and Usage in Unity:**

1.  **Import Script:** Add `UserSpiceOAuthHandler.cs` to your Unity project's `Assets` folder (e.g., in a `Scripts` subfolder).
2.  **Create Handler GameObject:**
    *   Create an empty GameObject in your scene (e.g., name it "UserSpiceOAuthManager").
    *   Attach the `UserSpiceOAuthHandler.cs` script to this GameObject.
3.  **Configure in Inspector:**
    *   Select the "UserSpiceOAuthManager" GameObject.
    *   In the Inspector panel, fill in the public fields of the `UserSpiceOAuthHandler` script:
        *   `User Spice Server Url`
        *   `Client Id`
        *   `Client Secret` (Be mindful of security implications - see PKCE note).
        *   `Auth Endpoint Path`, `Token Endpoint Path`, `User Info Endpoint Path` (defaults are provided).
        *   `Scope`.
        *   `Custom Uri Scheme` (e.g., `myunitygame` - just the scheme part).
        *   `Custom Uri Callback Path` (e.g., `oauth/callback` - the part after `://`).
4.  **Register Custom URI Scheme with the OS:** This is platform-dependent and crucial.
    *   **iOS:**
        *   In Xcode, go to your Target > Info > URL Types.
        *   Add a new URL Type.
        *   **Identifier:** Your app's bundle ID (e.g., `com.yourcompany.mygame`).
        *   **URL Schemes:** Your custom scheme (e.g., `myunitygame`).
    *   **Android:**
        *   Modify `Assets/Plugins/Android/AndroidManifest.xml` (create if it doesn't exist).
        *   Add an `<intent-filter>` to your main `<activity>`:
            ```xml
            <activity ...>
                <intent-filter>
                    <action android:name="android.intent.action.VIEW" />
                    <category android:name="android.intent.category.DEFAULT" />
                    <category android:name="android.intent.category.BROWSABLE" />
                    <data android:scheme="myunitygame" android:host="oauth" android:pathPrefix="/callback" />
                    <!-- Adjust host and pathPrefix to match your customUriCallbackPath if it has segments -->
                    <!-- For myunitygame://oauth/callback, scheme="myunitygame", host="oauth", pathPrefix="/callback" -->
                    <!-- If callback path is just "callback", then host="callback", no pathPrefix -->
                </intent-filter>
            </activity>
            ```
    *   **Standalone (Windows, macOS, Linux):**
        *   This is more complex. For Windows, it involves registry entries. For macOS, it's through `Info.plist` in the app bundle. For Linux, `.desktop` files.
        *   Often, for standalone builds, developers might opt for a localhost redirect (`http://127.0.0.1:PORT/callback`) and have the Unity app start a temporary local HTTP listener, similar to the Python desktop example. The `Application.deepLinkActivated` event might not work reliably for `http` schemes on all desktop platforms without specific OS integration or helper tools. The provided script assumes `Application.deepLinkActivated` will work if the scheme is correctly registered.
        *   If using localhost redirect for desktop: The `redirect_uri` in `StartUserSpiceLogin` would change to `http://127.0.0.1:PORT/yourcallbackpath`, and `OnDeepLinkActivated` might need to be replaced or supplemented with a local HTTP listener (e.g., using C#'s `HttpListener` class running in a separate thread). This script does NOT include a local HttpListener.

5.  **Update UserSpice Client Configuration:**
    *   In your UserSpice OAuth Server settings, ensure the **Redirect URI** for this Unity client is set exactly to what the script will use (e.g., `myunitygame://oauth/callback` or `myunitygame://callback` depending on your `customUriCallbackPath`).

6.  **Trigger Login:**
    *   From another script (e.g., a UI button's `OnClick` event), call:
        `UserSpiceOAuthHandler.Instance.StartUserSpiceLogin();`

7.  **Handle Events:**
    *   Subscribe to the static events to get results:
        ```csharp
        void OnEnable() {
            UserSpiceOAuthHandler.OnOAuthLoginSuccess += HandleLoginSuccess;
            UserSpiceOAuthHandler.OnOAuthLoginFailed += HandleLoginFailed;
        }
        void OnDisable() {
            UserSpiceOAuthHandler.OnOAuthLoginSuccess -= HandleLoginSuccess;
            UserSpiceOAuthHandler.OnOAuthLoginFailed -= HandleLoginFailed;
        }
        void HandleLoginSuccess(string userInfoJson) {
            Debug.Log("Login Succeeded! User Info: " + userInfoJson);
            // Parse userInfoJson and update game state
        }
        void HandleLoginFailed(string errorMessage) {
            Debug.LogError("Login Failed: " + errorMessage);
        }
        ```

**Important Considerations:**

*   **PKCE for Security:** As mentioned, using PKCE is strongly recommended for client-side applications like games to avoid embedding the `client_secret`. This would require modifications to this script and support from the UserSpice OAuth server.
*   **Error Handling:** The script includes basic error logging and events. Robust error handling and user feedback are essential in a production game.
*   **User Experience:**
    *   Provide clear feedback to the user that they are being taken to an external browser.
    *   Handle cases where the user cancels the login in the browser or if the app doesn't receive the callback (e.g., timeout).
*   **JSON Parsing:** The example uses `JsonUtility.FromJson` for the token response, which is simple but limited (requires class definition, public fields). For more complex JSON from the user info endpoint, consider using a more robust JSON library like Newtonsoft.Json (available as a Unity package or .NET Standard library).
*   **Platform-Specific Code:** While `Application.OpenURL` and `Application.deepLinkActivated` are cross-platform, the actual registration of custom URI schemes is platform-specific.
*   **Testing on Devices:** Custom URI scheme handling needs to be tested thoroughly on actual iOS and Android devices.
*   **Editor Testing:** `Application.deepLinkActivated` does not work in the Unity Editor. You'll need to manually simulate the callback by calling `OnDeepLinkActivated("yourcustomscheme://yourcallbackpath?code=testcode&state=teststate")` with test data or build to a device.
