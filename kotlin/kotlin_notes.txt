UserSpice Vanilla Kotlin OAuth Client Example
--------------------------------------------

This directory contains a basic Kotlin example of an OAuth 2.0 client for UserSpice.
It's designed to run on the JVM and uses standard Java libraries (like `java.net.HttpURLConnection`)
for HTTP requests, meaning it doesn't require external Kotlin-specific HTTP client libraries
like Ktor Client or OkHttp for this basic demonstration.

Files:
- OAuthClientConfig.kt: An object that holds the configuration for your OAuth client
  (client ID, secret, server URLs).
  **Important:** You MUST update the placeholder values in this file with your
  actual UserSpice server details and client credentials.
- OAuthRequest.kt: A standalone Kotlin script (`fun main`) that simulates the first step
  of the OAuth 2.0 authorization code flow. It constructs the authorization URL.
- OAuthResponse.kt: A standalone Kotlin script (`fun main`) that simulates the second step,
  handling the callback. It prompts for the 'code' and 'state', then exchanges the
  code for an access token.

How to "Run" (Simulate):
1. Ensure you have a Kotlin compiler installed (or a JDK, as you can compile Kotlin with `kotlinc-jvm`).
   You can download the Kotlin compiler from: https://kotlinlang.org/docs/command-line.html

2. Compile the Kotlin files. You'll need to compile them together or specify classpath if they are separate.
   Example (compiling all .kt files into a jar, then running specific main functions):
   `kotlinc-jvm OAuthClientConfig.kt OAuthRequest.kt OAuthResponse.kt -include-runtime -d oauth-kotlin.jar`

   This creates an executable JAR `oauth-kotlin.jar`.

3. Run OAuthRequest to get the authorization URL:
   `java -cp oauth-kotlin.jar OAuthRequestKt`
   (Note: Kotlin compiler appends 'Kt' to the class name for files with `fun main()`).
   - This will output a URL. In a real scenario, you'd open this in a browser.
   - It will also output a "generated state". Keep this value.

4. Simulate Authorization:
   - Imagine opening the URL in a browser, logging into UserSpice, and authorizing the application.
   - UserSpice would then redirect back to your specified `redirect_uri` with `code` and `state` parameters.
     Example: `https://your_app_domain.com/oauth_response_kotlin?code=SOME_CODE_FROM_USERSPICE&state=THE_STATE_YOU_GENERATED`

5. Run OAuthResponse to exchange the code for a token:
   `java -cp oauth-kotlin.jar OAuthResponseKt`
   - The program will prompt you:
     - "Enter the 'code' received from UserSpice:": Paste `SOME_CODE_FROM_USERSPICE`.
     - "Enter the 'state' received from UserSpice...:": Paste `THE_STATE_YOU_GENERATED`.
     - "Enter the original 'state' you stored...": Paste the "generated state" from step 3.
   - If successful, it will print the token response.

Alternative Compilation and Running (Individual Files):
If you prefer to compile and run files individually (less common for multi-file apps but possible for scripts):
`kotlinc-jvm OAuthClientConfig.kt -include-runtime -d config.jar`
`kotlinc-jvm OAuthRequest.kt -cp config.jar -include-runtime -d request.jar`
`java -cp "config.jar;request.jar" OAuthRequestKt` (Windows) or `java -cp "config.jar:request.jar" OAuthRequestKt` (Linux/macOS)
And similarly for `OAuthResponse.kt`. This gets more complex with dependencies. Using a build tool like Gradle or Maven is recommended for real Kotlin projects.

Important Considerations:
- This is a command-line simulation. Real web/mobile Kotlin apps would use frameworks (Ktor, Spring Boot, Android SDK) that handle HTTP and state management differently.
- Error Handling: Basic. Production apps need more.
- JSON Parsing: Prints raw token response. Kotlin apps often use `kotlinx.serialization`, Gson, or Jackson.
- Build Tools: For any non-trivial Kotlin project, use Gradle or Maven for dependency management and building.
- HTTPS: Assumes HTTPS.
- Configuration: Client ID/secret hardcoded. Use secure methods in production.
